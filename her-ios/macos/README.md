# Her macOS

Desktop companion for the Her Apple client family. Real signed Xcode app target, shares all backend / models / auth with iOS via the `HerShared` Swift package in `../shared`.

## Layout

```
her-ios/macos/
  HerMac.xcodeproj       Signed macOS app target, generated by scripts/create_xcodeproj.rb
  Sources/HerMac/        Swift sources (HerMacApp, HerDesktopView, HerAuthStore, Compat)
  Resources/
    Info.plist           Bundle Info: BackendAPIURL, NSMicrophoneUsageDescription, ATS exceptions
    HerMac.entitlements  Sign in with Apple, app-sandbox, network.client, audio-input
  scripts/
    create_xcodeproj.rb  Idempotent generator that produces HerMac.xcodeproj from this folder
```

Bundle id: `com.ekenesbek.her.mac`. Team: `6UNHXUUR5T`. Deployment target: macOS 14+.

## Build & Run From CLI

Use this when you do not want to open Xcode:

```bash
cd her-ios/macos
xcodebuild -project HerMac.xcodeproj -scheme HerMac -configuration Debug \
  -destination 'platform=macOS' -allowProvisioningUpdates build
open ~/Library/Developer/Xcode/DerivedData/HerMac-*/Build/Products/Debug/Her.app
```

The first command builds the signed Debug app, and the second opens the built `Her.app`. App logs only appear here when the app writes to stderr; use Xcode for interactive debugging.

Or open `HerMac.xcodeproj` in Xcode and hit Cmd+R.

`BackendAPIURL` defaults to the production server in `Resources/Info.plist`. Override with a local backend by editing that key, or set `HER_BACKEND_URL` in scheme environment (the `HerShared` `BackendConfig` reads it).

## Regenerate the project

If you add/remove Swift files under `Sources/HerMac/`, regenerate the project so Xcode picks up the file list. Editing existing files does not require regeneration; just rebuild or Cmd+R.

```bash
cd her-ios/macos
GEM_HOME=$HOME/.gem/ruby/2.6.0 ruby scripts/create_xcodeproj.rb
```

The script deletes and recreates `HerMac.xcodeproj`, wires the `HerShared` local package, adds the correct build settings and entitlements, and sets the same Team / bundle-id family as the iOS target.

## Auth & backend

- Sign in with Apple is the primary flow. The signed app has the capability, identity token reaches the backend.
- Backend `/v1/auth/apple` accepts both `com.ekenesbek.her` (iOS) and `com.ekenesbek.her.mac` (macOS) audiences via `APPLE_CLIENT_IDS`.
- Bearer session is persisted in the Keychain item `app.auth.session` (via `HerShared.KeychainSessionStore`).
- All `/v1/*` calls go through `HerShared.BackendClient`.

## What it does today

- Sign-in screen with native Apple Sign-In
- Home dashboard, Conversations list (in sidebar), conversation detail with audio player + Contents / Summary / Chat tabs
- Memory candidate review surface
- User popover from sidebar bottom: Settings link, Language submenu (placeholder), Log out
- Native macOS Settings scene for account / data / preferences

Not implemented yet:

- Native Google Sign-In on macOS (needs Google OAuth client id for macOS bundle)
- Microphone capture (entitlement is there, recorder is iOS-only — needs `#if os(macOS)` AVAudioEngine path in `HerShared` or `MeetingRecorder`)
- Audio playback transport wired to backend audio
- Memory candidate approve/reject mutations
