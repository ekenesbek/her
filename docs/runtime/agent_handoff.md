Use `cd her-ios/macos && xcodebuild -project HerMac.xcodeproj -scheme HerMac -configuration Debug -destination 'platform=macOS' -allowProvisioningUpdates build`, then `open ~/Library/Developer/Xcode/DerivedData/HerMac-*/Build/Products/Debug/Her.app`. The desktop UI matches the iOS black/white icon palette, has the design-matched `00 · sign in` split screen, routes existing authenticated accounts straight to the dashboard, routes new accounts into setup/onboarding, uses a Claude-style sidebar/account menu, removes the primary `Conversations` sidebar item and standalone top sidebar brand/status inset while keeping conversations reachable from recents/see all, uses a mutable native split-view sidebar toggle, shows conversation `Share`/`Export`/overflow actions in the native toolbar row, renders transcripts in the macOS contents tab from backend `segments` with `transcript` fallback, and now supports iOS-style chunk playback with active-row highlight and played-word blue text. Backend audio is preloaded for all returned audio-backed meetings into a local temp cache after meeting refresh and for the currently open conversation so first play does not block on a fresh download. Settings uses native macOS Settings via `SettingsLink`, and Settings rows now work: Billing, backend/account, conversations, People, memory, language, saved audio, legal/about/licenses, Help, JSON export, local toggles, backend voice-profile rename/delete, and sign-out routing are wired. Profile naming is intentionally local-only like the current iOS app: macOS onboarding and Settings persist `your name` / `agent name` to `UserDefaults` keys `app.settings.ownerName` and `app.settings.aiName`, merge the owner name into displayed `AuthUser`, and do not send profile names to the backend. Completing profile setup marks the Keychain session as existing so the next launch goes to the dashboard. Backend parity includes `HerShared` Keychain session storage, per-request bearer token source, Apple Sign-In client code targeting `POST /v1/auth/apple`, loopback-only local desktop bootstrap through `POST /v1/auth/desktop`, `/v1/auth/me` refresh, account-scoped meetings/subscription/voice profiles, and persisted meeting chat through `/v1/meetings/{id}/chat`. Server backend health was verified at `http://51.195.200.207:8787/health`. It is intentionally not wired into the existing iOS Xcode project yet.
